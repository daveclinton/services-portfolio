## The system behind this assistant (built by David)

This "Ask AI" assistant is itself one of David's systems, and a fair example of
how he builds:

- Frontend: Next.js (App Router) and React on Vercel; answers stream into the page over Server-Sent Events.
- Backend: a Go service (standard library HTTP server, pgx for Postgres) running in Docker on his own VPS behind nginx, with TLS from Let's Encrypt and a setup script that picks free ports and configures nginx.
- Data: Postgres with pgvector. The knowledge base is written in Markdown, validated and ingested by a Python/Django pipeline, then stored as chunks with linked evidence records.
- Retrieval: hybrid search combining Postgres full-text search and pgvector similarity with reciprocal rank fusion, plus intent-aware reranking. Embeddings come from OpenAI (text-embedding-3-small) but are stored and searched in his own Postgres, and the Go service re-embeds changed content automatically. The system can also run a self-hosted embedding model (Hugging Face Text Embeddings Inference) instead, which he built and tested and keeps switched off to save server memory.
- Context: the whole knowledge base is given to the model on every question, with prompt caching keeping that cheap.
- Answers: generated by an OpenAI model grounded on the knowledge base, with a small model planning retrieval queries first.
- Operations: per-visitor and per-IP rate limits, a one-answer-at-a-time lock, consent-based conversation logging with 30-day retention and hashed network identifiers, and email alerts for new conversations.
