Every post on this site is a single `.mdx` file in the repository. When the site builds, Next.js turns each file into a static HTML page, so reading a post costs one request and no client-side JavaScript.

## Writing a post

Create a file in `content/blog`. The file name becomes the URL:

```mdx title="content/blog/my-first-post.mdx"
export const metadata = {
  title: "My first post",
  description: "One sentence that shows up on the blog index.",
  date: "2026-10-27",
}

The body is plain **Markdown**, with React components available when I need them.
```

Commit it, push, and the deploy publishes it.

## Why not a CMS?

| | Files in the repo | Headless CMS |
| --- | --- | --- |
| Cost | Free | Usually a paid tier |
| Editing | My editor, with Git history | A web dashboard |
| Page load | Static HTML | Static HTML, or an API call |
| Code samples | Highlighted at build time | Often a plugin |

For a personal developer blog, Git already does what a CMS would: drafts live on branches, edits are reviewed as diffs, and every change has a history.

> The fastest page is the one that was already built before anyone asked for it.

## Drafts

Add `draft: true` to the metadata. The post shows up while I run `next dev`, and stays out of the production build.
